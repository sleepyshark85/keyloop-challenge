## What each suite is for

**`tests/unit/`** — The implementer's design tool: fast, no database, and the only suite Stryker measures.

**`tests/architecture/`** — Layering and containment, enforced by `dependency-cruiser` plus negative controls that plant a violation and expect rejection.

**`tests/contract/`** — Asserts the emitted OpenAPI document against the service — every error declared as `application/problem+json` on the operations that can produce it, by equality.

**`tests/property/`** — Generated inputs against an oracle — the availability query is checked against what the constraint actually permits, not against a fixture.

**`tests/integration/`** — Database invariants through the real schema: the exclusion constraints, the audit trigger, the telemetry spans.

**`tests/acceptance/`** — Drives the built artifact over HTTP. Defines *done* for a slice; the test-engineer writes these before any implementation exists.

**`tests/concurrency/`** — The system's central claim. Racers from a hard barrier against one slot; the DATABASE decides, and exactly one row survives.

**`tests/performance/`** — QS-14's budget, in its own Vitest project with its own container so it is never measured beside the twenty-racer suite.
