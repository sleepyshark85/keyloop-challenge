## 11.2 Known risks

Ordered by the cost of being wrong, not by likelihood.

### R-1 · The write-throughput ceiling bought with goal 1

§1.2 ranks integrity first and performance last with the cost stated; this is it. Two limits, routinely
confused. **Per contended key**, conflicting inserts serialise — three round trips per attempt, four for
a contended move — but only one succeeds, so what it caps is how fast losers hear *no*. **Measured:
229.47 attempts/s**, 20 racers onto one `(bay, technician)` pair in 87.2 ms, one `201` and nineteen
`409` on `cpus=16 i5-13400F`. **In aggregate**, every insert maintains two partial GiST indexes: low
thousands per second.

**Binding scale.** Against §1.1's *tens of appointments a day*, the contended figure binds at roughly
two hundred simultaneous bookers on one slot — which no dealership generates organically; it arrives as
a campaign funnelling many at one advertised slot — and the aggregate limit above binds first.
**The first move is partitioning by `dealership_id`**, which A-9 permits: an exclusion constraint
cannot span partitions and need not.

### R-2 · A capacity-*n* resource needs a different mechanism (A-2)

An exclusion constraint expresses capacity **one**, so a technician overseeing two jobs makes it the
wrong shape. The cheapest route changes the model: *n* numbered slots, each capacity-one, so only
candidate generation changes. A counting constraint, or `SERIALIZABLE` plus an application count, moves
correctness back into code (§2.1).

### R-3 to R-6 · Four couplings that nothing structural enforces

**R-3** — the constraint names are behaviour: the retry loop prunes from `err.constraint` and §8.4 labels
the counter from it, so renaming `no_bay_overlap` degrades the loop and mislabels the metric. Held by
QS-1 and QS-2. **R-4** — the attempt cap can refuse while capacity exists, 16 being below the structural
bound `|bays| + |technicians| − 1`. [ADR-0040](../adr/0040-order-candidates-free-first-from-one-advisory-read.md) spends those attempts
free-first, so attempt 16 now takes fifteen conflicts among candidates the advisory read called free:
**unlikely rather than impossible** — probabilistic where a larger cap would be structural. **The counter
is still not a clean signal.** Measured single-threaded at eleven of twelve pairs occupied: **163 of 200** confirmed before, **200 of 200** after (QS-15; the red figure is a sample,
`R-19-5`). The residual now needs a burst, which nothing in the suite can falsify (D-19-3).
**R-5** — the constraint's range expression and the availability query's are one idea in two files with
no runtime signal, held by QS-8 alone. **R-6** — the `Database` interface can drift from the migrations,
held by nothing.

### R-7 to R-12 · Smaller gaps, recorded so they are not discovered

**R-7 · structural residue.** The transaction boundary must be exactly one attempt wide and nothing
enforces it — wider, the second attempt fails `25P02`; narrower, `pg_advisory_xact_lock` has no
transaction to scope to. The seed must vary per request; down migrations are exercised by no test; and
the RFC 3339 pattern is a regex, so `2026-02-30T10:00:00Z` is accepted.
**R-8** — three things CI is *said* to enforce and does not: the diagram scripts cannot run, link
integrity is only partial, and **no tool checks that a `QS-*` names a real test**.
**R-9** — `db:migrate` invokes the CLI binary where ADR-0007 says *"programmatically"*: an accepted
decision the code silently stopped implementing, to be conformed rather than superseded.
**R-10** — `updated_at` is maintained by the writer with no trigger, and only the *holding* half of
cancellation's `CASE` is asserted.
**R-11** — four reference-table constraints (`day_of_week BETWEEN 0 AND 6`, `closes_at > opens_at`,
`duration_minutes > 0`, `vehicle.vin UNIQUE`) are asserted by nothing. **Three now have hand-run evidence
and still no committed assertion**: slice 15 drove `harness/seed.mjs` at three fixtures violating those
CHECKs and each was refused with PostgreSQL's own SQLSTATE and rolled back to zero rows — a measurement
in a report, not coverage, and `vehicle.vin UNIQUE` is untouched. The criterion was refused inside slice
15 because the transaction it would ride on was already built, so it could not be red first (§2.4). And
`appointment_technician_in_dealership` is proven to exist and not to fire, so the technician half of A-9
rides on a catalogue assertion and the bay half on a behavioural one.
**R-12 · the mutation gate's failure mode is silence.** Stryker has a demonstrated mode in which it
reports survivors it never tested — twice, each caught by a low score, which is luck — and is blind to
guards outside `tests/unit/`, so `telemetry.ts` first read **12.82**.

## 11.3 What production would additionally require

Scope cut deliberately is judgement; cut silently it is a gap. Every item traces to a §3.3 exclusion or
a Gate A ruling. **Authentication and authorisation** (GC-2) is the first, and is not additive:
ownership moves into a security boundary, `422` becomes `403`, and every test on that shape is revised.
**Technician shifts, holidays and absence** (ADR-0001) is the expensive one — time-varying per-resource
availability is a *second* class of rule beside the database-enforced one, with its own concurrency
story. **Appointment history and audit** (ADR-0003) is additive: an append-only table. **DMS event
publication** is an outbox row in the same statement. **High availability, backup and recovery** is
ordinary PostgreSQL operations, the application being stateless. **Vehicle-dependent durations** (A-1) and **buffers** (A-4) are one domain function plus one migration
each (QS-12); **search-style booking** (A-5) turns the advisory read into allocation and is larger.
**Reference-data management** (A-7) is conventional CRUD. **Waitlists, overbooking and priority jobs**
are where a real scheduler earns its keep. **GDPR-grade PII handling** — retention, subject access,
erasure — touches the history table above; today customer names are stored and logs carry ids only
(§8.4).
