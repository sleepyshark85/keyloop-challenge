# Slice 16 — design · [`16-availability-derives-its-own-window.md`](16-availability-derives-its-own-window.md) · arc42 §6.5, §8.6, §10.2, §11.1 · [ADR-0039](../adr/0039-availability-takes-a-start-not-a-window.md) · step 1

## 1 · What changes

Discharges the human's gate finding `H-16-1`. `GET /availability` stops taking `from`/`to` and
takes `startsAt`; `queryAvailability` calls
`deriveInterval(startsAtMillis, serviceType, dealership)` — **the function `bookAppointment` calls,
unedited** — and the `200` carries the derived `startsAt`/`endsAt` it answered about. Three things
follow from reusing that function rather than writing a second derivation, and each is worth more
than the parameter change itself: duration arithmetic stays in `duration.ts` (QS-12); the
opening-hours gate comes along (§5, ruling 5); and the window becomes a value two responses can be
compared on (AC-2) instead of a fact only the server knows.

## 3 · Interfaces

```
GET /availability?dealershipId&serviceTypeId&startsAt
200 { startsAt, endsAt, bays[], technicians[], advisory, disclaimer }
```

```ts
export interface AvailabilityQuery {
  readonly dealershipId: string;
  readonly serviceTypeId: string;
  readonly startsAtMillis: number;   // the same shape BookCommand takes
}

export type AvailabilityOutcome =
  | { kind: 'available'; startsAt: Instant; endsAt: Instant;
      bays: readonly string[]; technicians: readonly string[] }
  | { kind: 'malformed-instant' }                                   // 400 malformed-request
  | { kind: 'outside-opening-hours'; verdict: OpeningHoursVerdict }  // 400
  | { kind: 'unknown-reference'; reference: 'dealership' | 'service-type' }  // 422
  | { kind: 'reference-data-invalid'; detail: string };             // 500
```

`malformed-window` is **gone, not renamed**. It existed to hold two cases under one member —
`to <= from` and an unrenderable bound — with a docblock arguing there is no second fact a client
could act on. One of those cases is now unreachable by a client and the other is exactly the
booking path's `malformed-instant`, so the member the two endpoints share is the one that survives.
That convergence is the taxonomy ruling (§5, ruling 3) rather than a rename.

**Statement order becomes `bookAppointment`'s exactly**: dealership → service type →
`deriveInterval` → candidates → busy. Today availability checks the window first, so
`{unknown dealership, garbage startsAt}` answers `400` from availability and `422` from booking.
Nobody reported that; it is the same defect in a second dimension, and adopting the booking path's
order closes it for free. AC-4's last clause is what pins it.

The busy read uses the derivation's **occupancy** interval (what the constraint sees); the response
names the **appointment** interval (what the client asked about). A-4 makes them identical today,
and `occupancyInterval` is the one place that changes if a buffer ever arrives.

## 4 · Data-model delta

**None.** No migration, no column, no index. The exclusion constraints, `busyResources` and
`candidateResources` are untouched.

## 5 · Rulings

### Ruling 1 — replacement, not addition

**`from`/`to` go away.** Keeping them alongside `startsAt` keeps the reported defect available on
the same URL: a caller can still name a window that is not the interval a booking would occupy, and
the endpoint still cannot promise it answered the brief's question (*"for the entire service
duration"*, `Requirements.md:31`). An addition would also double a taxonomy this slice is
simplifying — `to <= from` returns from the dead — for a mode with no consumer, and TypeBox cannot
express *either these two or that one* in an object querystring that `@fastify/swagger` explodes
into flat parameters, so the contract could not even state the exclusivity it would depend on.

The reversal cost is small and I have counted it: two schemas, one union, one property test, one
performance test, one `curl` in the walkthrough. Nothing external consumes this API.

**The strongest argument for keeping the range is not the one it looks like.** A one-day query
sounds like a booking screen's day view. It is not: over 24 hours it reports a bay free only if
that bay is free for the *entire day*, which in a working dealership is almost never, and it never
tells a caller *when*. The range interface's only honest use is when the range equals the service
duration — which is what this slice makes the only thing it can be. The genuine day-view question
("which start times are free today?") wants a different endpoint returning instants, not resource
ids; ADR-0039 records it as deferred rather than rejected.

### Ruling 2 — what QS-8 asserts now

QS-8 keeps its shape and its six mechanics; the generator gives up `to` and gains `startsAt`, and
**the probe interval is read from the response**. That is the whole amendment, and it is what stops
the property becoming a second implementation of the derivation. Two consequences I want on the
record before the test is written:

- **QS-8 is now internally consistent by construction and cannot catch a wrong window.** A server
  that derived 30 minutes for a 60-minute service would answer about 30 minutes, be probed over 30
  minutes, and pass. **AC-2 is the assertion that catches it** — the availability answer and the
  booking answer must name the same two instants. Splitting the claim across a property and an
  acceptance criterion is honest; folding it into QS-8 would look stronger and be weaker.
- **Aiming and probing are different privileges.** The generator may use the fixture's declared
  duration to place appointments on the derived boundaries — a generator that aims badly only
  wastes cases. The probe may not, ever.

### Ruling 3 — the residual error taxonomy

With `to` derived, `to <= from` is unreachable and `malformed-window` has nothing left to hold.
What remains, and what each answers:

| Outcome | Answer | What it tells the client to do |
|---|---|---|
| `startsAt` is not a renderable instant | `400 /problems/malformed-request` | Send a different instant |
| Unknown dealership or service type | `422 /problems/unknown-reference` | Fix the id you named |
| The derived interval leaves opening hours | `400 /problems/outside-opening-hours` | Ask about a different time — nothing about the resources is wrong |
| Duration or opening-hours reference data unreadable | `500 /problems/internal` | Nothing. It is not yours to correct |

Every row is the booking path's row for the same input, which is the point: the two now differ only
where they must (`vehicle-not-owned` books, availability does not; `no-capacity` is adjudicated by
an `INSERT` availability never performs). §8.6 gains **one word** — `availability` on the
`outside-opening-hours` row. The `500` row already reads *all five*.

### Ruling 4 — this warrants an ADR, and I agree with the orchestrator

Under the human's bar it clears both halves. It **closes off an alternative someone would
reasonably take**: a `from`/`to` range is what almost every scheduling API does, and the next agent
to touch this endpoint will reach for it unless something says why not. And it is **expensive to
reverse** — not in lines of code but in what was built on it: QS-8 probes what the response names,
QS-14 measures a window nobody chooses, and the published document declares three parameters.
Reversing means re-widening a contract and re-amending two quality scenarios.

There is also a rule here wider than one endpoint, which is the real reason to write it down: **a
client is never asked for a value the server can derive.** That governs the next endpoint too.

### Ruling 5 — availability applies opening hours, and this is not scope creep

**It is the cheaper option, which is what settles it.** `deriveInterval` returns a discriminated
union in which `outside-opening-hours` carries no interval. To have availability ignore opening
hours I would have to either not call `deriveInterval` — writing a second derivation, defeating the
slice — or change `deriveInterval`'s signature to hand back an interval it currently refuses to
produce, editing the booking path's core module for the sole purpose of weakening this endpoint.
Excluding the gate costs a special case; including it costs nothing.

The criterion, since one is owed either way: **AC-1**. Without opening hours this slice would ship
an endpoint that reports a bay free at 03:00 on a Sunday and a booking that refuses it `400` — the
human's reproduction with a different status code, in the slice whose thesis is that the two agree.

### Ruling 6 — `I-16-1`, **(a) clarification**: the two helpers are not the same kind of thing

The implementer put `outsideOpeningHours` and `INTERNAL` to me as one choice over two symbols. They
get **opposite answers**, and the split is the ruling.

**`outsideOpeningHours` is exported and shared** because it is a *function over a domain union with
a branch* — it inspects `verdict.kind` and attaches `opensAt`/`closesAt` only for `outside-window`
(`appointments.ts:463-478`). Duplicating a derivation over a domain value is **ADR-0039's own
category**, refused for the same reason there. Its docblock already claims a sharedness that a copy
would falsify — *"the SAME domain rule both routes render, not a second copy of it … which is why
this takes `OpeningHoursVerdict` directly"* — a signature written to admit a caller it did not yet
have, the same instinct that makes `deriveInterval` callable unedited.

**`INTERNAL` is rebuilt locally** because **this repository already ruled that
`/problems/internal` is duplicated by construction site and held in agreement by the contract
test**, not by shared code. The two existing sites are `src/http/server.ts:305` and
`src/http/routes/appointments.ts:484` — identical `type`, status, title and `detail` — and
`appointments.ts:481` says so on purpose. **There is no response schema to share**: the `500`
deliberately carries none (`appointments.ts:149-150`, I-02-5). A frozen const with no branch has
nothing to drift but a string `tests/contract/error-taxonomy.test.ts` reads. A third site follows a
settled precedent.

`availability.ts`'s map is therefore:

```ts
const PROBLEM_RESPONSES = {
  400: problemResponse('/problems/malformed-request', '/problems/outside-opening-hours'),
  422: problemResponse('/problems/unknown-reference'),
} as const;   // no 500 — the catch-all cannot afford a schema of its own
```

**Two members at `400` is load-bearing, not incidental** (I-10-1): a one-member `Type.Union`
collapses to a Literal and *silently substitutes*. The `422` cell is single-member and needs the
hand-built `Type.Unsafe` shape slice 10 adopted.

*On "it edits a file the design says is untouched": the edit is the keyword `export`. Route→route
import is already the shape here — `availability.ts` imports `RFC3339_PATTERN, UUID_PATTERN` from
`./appointments.js` today.*

The scope ruling and the corrected ownership count live in

### Ruling 8 — `T-16-1`: **no test, and no `Stryker disable` directive**

The test-engineer is right that the occupancy/appointment distinction must not become a test, for a
sharper reason than it gave. **While A-4 holds the buffer at zero the two intervals are the same
value**, so a test could only assert `x === x`: it would *pass against the mutant it was written
for*, and would have failed at no point in its life. §2.4 is explicit that a test which has never
failed is not evidence.

**No directive either, and this is the half that matters.** The imagined mutant is a swap between
two identically-valued expressions; **Stryker does not synthesise those**. There is no mutant in the
report to suppress, and a directive would strip *real* mutants from the denominator — exactly what
`O-62` declined to do at `availability.ts`'s `never` arm.

**Where I disagree: a code comment alone is not the record.** The claim outlives the function that
carries it, and its reader is whoever introduces a buffer years from now, who reaches §6.5 first.
Two homes, different content, different steps:

| Home | Owner · step | Content |
|---|---|---|
| arc42 §6.5 | architect · **step 7** | The busy read uses the occupancy interval, the response names the appointment interval; A-4 makes them identical, `occupancyInterval` is the single site a non-zero buffer changes, and the distinction is consequently unasserted by any test |
| `src/application/queryAvailability.ts` | implementer · **step 4** | A short comment where both are named, **citing §6.5 and A-4** rather than restating them |

Not a §11 debt row: nothing is owed and there is no work to book.

## 8 · Where I disagree with the framing I was given

- **`harness/` and `README.md` are not touched.** No harness script calls `/availability`
  (`grep` over `harness/`: nothing) and the README's single mention is prose about a scenario, not
  a request. Both were listed as touched; both are out.
- **The retired-ADR citation is not one line, it is ten** — two in `src/`, seven in `tests/`, one
  in `queryAvailability.ts`. Roles fix what they are already rewriting; the sweep is booked
  (`F-16-1`). Calling it minor understated it, and the interesting part is that a retirement pass
  advertised as rewriting ~160 references left a whole endpoint's cluster behind.
- **I found a second instance of the same defect class and it is in scope**: the two endpoints
  disagree today on *precedence* between an unknown reference and a bad instant (§3). Same root —
  availability deciding the window before anything else — closed by the same change.
- **And a third that is not in scope**, `F-16-2` above: §8.6 says availability answers `422` for a
  service type nobody there is qualified for; it returns empty lists. Recorded, not fixed.
- **Nothing here suggests the slice is wrong.** It is the smallest change that makes the endpoint
  able to answer the question the brief asks, and the human's reading of §11 is right — the choice
  was never recorded because it was never made.

## 9 · Assumptions and open questions

- **A-16-1** — that no client outside this repository consumes `from`/`to`. Stated by the
  orchestrator, consistent with the brief's stubbed client layer, and the whole basis of ruling 1.
  If it is false, this is a breaking change and ADR-0039 should be re-argued at the gate rather
  than by me.
- **A-16-2 — resolved at step 2.** `500 /problems/internal` *is* reachable through a seedable
  dealership with unreadable opening hours: `tests/contract/error-taxonomy.test.ts:402-467` already
  reaches it for booking through the `timeZone: 'Not/AZone'` fixture — a real row, a real
  unparseable zone, no mock, §2.2 intact — and availability inherits the route the moment it calls
  `deriveInterval`. **AC-4's last row stands as written**; nothing is carried to the gate.
- **OQ-16-1 — confirmed at step 2: no duration field.** Two instants already state the duration and
  a third value is a second thing to keep in agreement, but the sharper reason is that **AC-2
  compares instants**, so a minutes field would be the only member of the `200` no acceptance
  criterion can fail. Adding an unassertable field in the slice that exists to make two responses
  provably agree is the wrong direction. **The caveat, since I will not overstate it:** ADR-0039's
  rule — *a client is never asked for a value the server can derive* — is about **requests** and
  does not decide this either way; `endsAt` is itself derived and belongs in the body. The refusal
  rests on redundancy and agreement cost alone. If the gate wants the field it is cheap and should
  arrive with an AC-2 clause.
